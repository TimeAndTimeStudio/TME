# Build Process

## Requirements
- `TSL/` directory cloned from official repository at `https://github.com/TimeAndTimeStudio/TSL`
- `game.tsl` — Game source file
- `index.html` — Must contain `<canvas id="game"></canvas>`
- `style.css` — Optional user styles

## Commands

### `tme init [directory]`
Creates a minimal starter template in the specified directory (or current directory if omitted).

**Creates:**
- `game.tsl` — Starter game source
- `index.html` — HTML with required canvas element
- `style.css` — Empty starter CSS

**Safety:** Does not overwrite existing files. Reports conflict and stops if files exist.

### `tme build`
Compiles TSL, packages runtime, and outputs to `dist/`.

**Build Stages:**
1. Validates project structure and required files
2. Validates `<canvas id="game">` exists in `index.html`
3. Invokes TSL to compile `game.tsl`
4. Packages TEMF runtime and TME engine
5. Preserves user HTML/CSS without modification
6. Copies user directories recursively to `dist/`
7. Outputs static package to `dist/`

## Output Structure
```
dist/
├── index.html          # User-owned, preserved
├── game.js             # Generated by TSL
├── engine.js           # TME engine runtime
├── style.css           # User-owned, preserved
└── <user directories>  # Copied recursively
```

## Build Rules
- User HTML/CSS preserved across builds
- User directories copied recursively with arbitrary names (e.g., `images/`, `sprites/`)
- Static export — no npm dependencies at runtime
- TSL failure causes build failure (no fallback)
- Missing `canvas#game` stops build before TSL invocation
- Engine-owned outputs: `game.js`, `engine.js`
- User-owned inputs: `index.html`, `style.css`, all other files

## Deployment
- Upload `dist/` to any static hosting service
- No server-side processing required
- Compatible with browser-based execution
